## Dataset v1

The first structural pass uses exactly 5,000 transactions generated by the Debug-only `PerformanceAuditDataSeeder`.

- Anchor: `2026-10-09T12:00:00Z` (`1791547200`)
- Span: five years
- Currency: EUR
- Mix: one deterministic income every 20 records; remaining records are expenses
- Categories: all default income and expense categories, sorted before assignment
- Budgets: deterministic budgets on Groceries, Restaurants, Gas, and Streaming Services
- Debug fixture PIN: `1234`, with biometric lock disabled
- Not included yet: goals, travels, recurrence rules, multiple currencies

The missing entity types are an explicit limitation. Dataset v1 is sufficient to measure refresh/fetch multiplicity. It is not yet representative enough for final timing or energy conclusions.

The seed launch is destructive to the selected simulator store and must be used only with the dedicated worktree simulator:

```bash
rtk xcrun simctl launch --terminate-running-process <UDID> rizzoG99.PersonalFinanceTraker \
  -performanceAudit \
  -performanceAuditScenario seed-5k \
  -seedPerformanceAuditData 5000 \
  -performanceAuditAnchorEpoch 1791547200 \
  -hideTips \
  -feature_discovery_has_completed_tour YES
```

Terminate the app after the seed completes. Do not pass `-seedPerformanceAuditData` during measured runs, because seeding is deliberately excluded from startup and refresh measurements.

## Instrumentation contract

Instrumentation is disabled by default. Enable it with `-performanceAudit` or `PFT_PERFORMANCE_AUDIT=1`; label each launch with `-performanceAuditScenario <name>`.

The unified log uses subsystem `rizzoG99.PersonalFinanceTraker`, category `PerformanceAudit`, and prefix `PFT_PERF`. Points-of-interest intervals use the same subsystem.

Recorded structural metrics:

- `TransactionActor.fetchAll` count and duration
- Dashboard, Activity, and Insights load request/start/commit/end counts
- skipped guarded loads and concurrent loader maxima
- `DataChangedSignal.bump` and shell fan-out counts
- bootstrap and foreground refresh intervals
- Habit and Safe-to-Spend refresh/write counts
- WidgetKit timeline reload request counts by widget kind

Collect the log with:

```bash
rtk xcrun simctl spawn <UDID> log stream --style compact --level info \
  --predicate 'subsystem == "rizzoG99.PersonalFinanceTraker" AND category == "PerformanceAudit"'
```

The existing widget-destination launch path can open Insights once without UI automation. Use it only for the settled navigation scenario:

```bash
rtk xcrun simctl launch --terminate-running-process <UDID> rizzoG99.PersonalFinanceTraker \
  -performanceAudit \
  -performanceAuditScenario open-insights-5k \
  -performanceAuditSkipLock \
  -pending_widget_destination insights \
  -hideTips \
  -feature_discovery_has_completed_tour YES
```

This uses `-performanceAuditSkipLock`, a Debug-only launch gate. It is valid for a settled navigation scenario but must never be used for cold-launch or authentication measurements.

## Evidence boundary

Simulator/Debug results can confirm duplicate calls, event ordering, commits, cancellations, and overlap. They cannot establish user-facing timing, memory, energy, or camera performance. Those conclusions remain gated on an optimized build and physical devices with thermal state, OS version, run count, and Instruments templates recorded.
