# Feature: Budgets (per-category, pay-cycle-native)

## Problem
Users have no way to set a spending limit per category and see whether they're on track — the
#1 gap vs. every manual-entry competitor (MoneyCoach, Cashew, YNAB).

## Approach
Per-category budgets only (no overall/whole-ledger budget). One SwiftData model (`BudgetModel`)
storing a standing target amount per category — no stored "cycle" or "period" field. Progress is
computed on demand each time it's needed: `PayCycleService` gives the current cycle's date range,
and the same fetch-all-then-filter-in-memory pattern already used by `SpendingInsightService` sums
that category's spend within it. The budget "resets" automatically because each cycle just queries
a fresh window — no explicit reset job or scheduled task.

This beats a snapshot-history model (persisting a record per cycle, like `HealthScoreSnapshot`)
because nothing in scope needs historical budget trends yet, and a snapshot table wouldn't reduce
the live-progress computation cost anyway (that still requires scanning the current cycle's
transactions). Snapshotting can be layered on later without changing the `BudgetModel` shape if a
"did I hit budget last month" view is wanted.

Performance: verified the existing `TransactionRepository.fetchAll()` + in-memory filter pattern
(used throughout `SpendingInsightService`, e.g. `heroInsight`) already loads the full ledger on
every Dashboard/Insights load, regardless of budgets. Adding one more per-category, per-cycle
filter-and-sum pass is cheap relative to that. If `fetchAll()` itself ever needs to become a scoped
`FetchDescriptor`, that's a repo-wide change orthogonal to this feature.

## Key decisions
- **Per-category only** — no overall budget across all categories.
- **Dedicated Budgets screen**, reached from the Profile bottom sheet — not inline on the
  Categories screen.
- **Dashboard surfaces near-limit categories only** (progress bars for categories approaching
  their budget), full list with all categories lives on the Budgets screen.
- No stored per-cycle snapshots — budget progress is always computed live against the current
  pay cycle.
- Categories with no budget set simply don't appear in budget UI (no default/implicit budget).

## Open questions for implementation session
- Exact "near-limit" threshold for the Dashboard callout (e.g. ≥80% of budget spent) and how many
  categories to show if several qualify.
- Whether exceeding a budget needs any notification/alert, or stays purely visual (progress bar
  turning red/over) — out of scope for this brainstorm, decide when scoping recurring
  transactions/reminders next.

## Architecture notes
Where this fits in the existing codebase:
- **New SwiftData model**: `BudgetModel` (category name string — matching `TransactionModel`'s
  category convention —, target amount `Decimal`). Add to the SwiftData schema; no migration
  needed per project policy (reinstall is fine).
- **Repository**: extend `ITransactionRepository` (or add a sibling protocol) with
  `fetchBudgets()` / `saveBudget()` / `deleteBudget()`, following the existing snapshot +
  protocol pattern (`BudgetSnapshot` value type, mirroring `CategorySnapshot`).
- **New service function**: add budget-progress computation to `SpendingInsightService` (or a
  small sibling), taking `[TransactionSnapshot]` + `[BudgetSnapshot]` + the current
  `PayCycleService` window and returning per-category spent/remaining/percent.
- **New feature folder**: `Features/Budgets/` — `BudgetsView`, `BudgetsViewModel`,
  row edit UI reusing existing amount-entry patterns from the Add/Edit Transaction sheet.
- **Modify**: Profile bottom sheet to add a "Budgets" entry point; `DashboardView`/
  `DashboardViewModel` to add the near-limit progress bar section, reusing the snapshot pattern
  already used for the balance card / recent transactions.
- No changes needed to `PayCycleService` or `TransactionModel` — both are reused as-is.

## Where to start
Add `BudgetModel` to the SwiftData schema and a `BudgetSnapshot` value type + repository CRUD
methods, following the existing `CategoryModel`/`CategorySnapshot` pattern as the template —
that unblocks both the Budgets screen and the Dashboard progress bars.
